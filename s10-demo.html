Session 10 Demo — Container, Cards & CSS Order

Layout with .container and .card, cascade (order of stylesheets), buttons, and <span class="highlight">.

From class: Inline style first, then external CSS

Order matters. In the <head>, the inline <style> comes before the external stylesheet. The browser applies CSS in order, so s10-styles.css can override the inline rules (e.g. p { color: purple; }).

<style> h1 { /* color: red !important; */ /* !important wins over later styles */ } p { color: purple; } </style> <link rel="stylesheet" href="/css/s10-styles.css" />

Layout: A .container wraps multiple .card divs to group content into panels. External CSS typically makes the container a grid or flexbox and styles each card (border, padding, background).

What we learned

  • CSS load order (cascade) — Stylesheets and <style> are applied in the order they appear. A later rule (e.g. in s10-styles.css) overrides an earlier one when specificity is the same.
  • !important — Forces a property to win over other declarations. Useful for overrides but use sparingly; it can make debugging harder.
  • Container + cards — .container holds the layout (e.g. grid/flex); .card wraps each block of content. A common pattern for dashboards, galleries, and feature sections.
  • <span class="highlight"> — Inline element for highlighting part of a sentence without changing the block structure.
  • <button> — Use type="button" for click actions (so it doesn’t submit a form). Style with a class (e.g. .button) for consistency.
HTML tip: Keep the <span> inside the <li> and wrap the link: <li><span class="highlight"><a href="...">...</a></span></li>. Close the span before closing the li so markup stays valid.
