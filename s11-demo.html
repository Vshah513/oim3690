Session 11 Demo — Multiple Classes & Modifiers

Building on container + cards: using class="card my-element" to combine layout with a modifier or hook.

From class: Same page as Session 10, with an extra class

Session 11 uses the same structure as Session 10 but loads s11-styles.css and adds a second class to the first card:

<div class="card my-element"> <!-- first card: gets both .card and .my-element styles --> ... </div> <div class="card"> <!-- second card: only .card --> ... </div>

Why two classes? .card gives the shared layout (border, padding, background). .my-element can add extra styling for this specific card (e.g. highlight, accent border) or be used as a hook for JavaScript (e.g. document.querySelector('.my-element')).

What we learned

  • Multiple classes on one element — class="card my-element" means the element matches both .card and .my-element. You can style it with .card { ... }, .my-element { ... }, or .card.my-element { ... } for rules that apply only when both are present.
  • Base + modifier — .card is the base; .my-element is a modifier. One card gets the modifier (accent border, highlight); the other stays default. This pattern scales to many cards with a few variants (e.g. card featured, card muted).
  • JavaScript hooks — Classes like my-element are easy to target in JS (querySelector('.my-element')) without changing the visual design. Use meaningful names (e.g. card-featured, js-expand) for clarity.
  • Separate stylesheet per session — Using s11-styles.css keeps Session 11’s overrides and new rules in one place, so you can compare or swap styles without touching the HTML structure.
